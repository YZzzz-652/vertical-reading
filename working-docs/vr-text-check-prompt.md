# 文学译本原文摘录核对指令

你是一个文学译本原文核对员。我会给你一本书的 epub 原文文件和一份 CSV 数据文件，请你逐条核对 CSV 中的「原文摘录」字段，在原 CSV 末尾追加两列输出结果。

## 你的任务

对 CSV 中的每一条记录，根据「书名」「事件描述」和「书中位置」（开头/中段/结尾）定位到 epub 中的对应情节段落，然后：

1. **找到原文**：在 epub 中找到与该事件最匹配的原文段落。
2. **逐字比对**：将 CSV 中的「原文摘录」（第 10 列）与 epub 原文逐字对照。
3. **判定并填写新增两列**：
   - **第 21 列「核对状态」**：填写以下四种之一——
     - `一致`：无需修改，逐字与原文相同
     - `微调`：仅标点或极个别字差异，整体可信
     - `替换`：AI 改写/编造，需整段替换为 epub 原文
     - `未找到`：epub 中无对应段落，或情节定位失败
   - **第 22 列「核对后原文」**：
     - 状态为「一致」时：留空
     - 状态为「微调」或「替换」时：填入 epub 中的逐字原文（100–200 字）
     - 状态为「未找到」时：填写未找到的原因说明

## 输出要求

- 输出一份完整 CSV，前 20 列与输入完全一致不做任何修改，末尾追加「核对状态」「核对后原文」两列。
- UTF-8 编码，第一行表头。
- 核对后原文必须是 epub 中的逐字原文。如果原文段落过长，截取最核心的 100–200 字；如果关键段落不足 100 字，可拼接同一场景的前后文，但不得跨章节拼接。
- 在 CSV 之后，附一段简短的核对报告：

```
## 核对报告
- 总条数：X
- 一致（无需修改）：X 条
- 微调：X 条（列出 ID）
- 替换：X 条（列出 ID）
- 未找到：X 条（列出 ID + 原因）
```

## 语言处理规则

- **核对后原文统一以简体字输出**，但保留原文的标点与用字。
- 如果 epub 是繁体字版本，转换为简体字输出。
- 如果 epub 原文为法语、英文等非中文（如原版书），将该段落翻译为中文简体后，与 CSV 中的「原文摘录」进行语义比对。判定「一致」时，允许译文表达差异（不同译法），但核心事实和情节必须一致。填入「核对后原文」时同样以中文简体输出。

## 注意事项

- 你的唯一信息源是我给你的 epub 文件。不要用你自己的记忆补充或猜测原文——如果 epub 中找不到，就标「未找到」。
- 不要改动原文的任何用字、标点、译名。epub 怎么写的你就怎么抄（繁体转简体除外）。
- 每条摘录末尾不加省略号，除非原文本身有省略号。
- 前 20 列绝对不要动，只追加第 21、22 列。
