## 流程决策

2026-06-03 · 文档体系 consolidation
- 决定：对全套文档做一次系统性重整——
  ① 拆 AGENTS：文档路由表留 AGENTS（读时用），文档维护机制（颗粒度/触发/维护/归属/归档/更新指令规范）摘为独立《文档维护规范》（写时用）；
  ② 决策日志按上线节点拆「当前」+「归档_上线前」，当前文件加「当前目录」与「归档地图」；
  ③ 数据库文档由归档翻回 active、按开工顺序重排、立"单选/多选不用兜底值、绝不写其他"规则；订正字段——细描标签=自由文本身份词、事件类型=独立第 20 列多选；
  ④ 新建《书目清单》记录数据生产进度（动态，状态 + 条数 + ID 前缀）；
  ⑤ 项目启动文档瘦身为现状 + 待办，删除历史 Roadmap（迁入本归档「阶段演进史」）；
  ⑥ 设计规范瘦身为意图 + 不可违反原则 + 指针。
  启动与读取由"读全部文档"改为"读脊柱（AGENTS + 项目启动文档）+ 按路由"。
- 原因：5 份文档每次全量读消耗近 20% 对话 token，纯代码/数据任务也被迫读全套；决策日志越来越长、早期决策与当前工作无关；多处重复（数据坑/技术栈/字体规则在多文档各写一份）；缺少明确的"什么事实进哪个文档"的归属规范。
- 否定方案：① 删除早期决策来压缩决策日志——违反"永不删历史"原则、丢失"别重蹈被否方案"的审计价值，改用"路由摘出 + 归档 + 索引"；② 决策日志按内容拆成多个独立文件——对当前体量过度工程，时间拆 + 分类索引已够，待「当前」自身变大再按类拆；③ 把路由表也一起摘进维护规范——鸡生蛋（要知道读什么得先读它），路由表须留在脊柱。
